# 신뢰도·전문성 강화 + 데이터 기반 후기·합격 사례 (설계)

작성일: 2026-10-12 / 브랜치: `site-trust` / 대상: https://edu-solution.co.kr

## 1. 목표와 성공 기준

- **목표**: 방문자가 "여기는 믿고 맡길 만하다"고 느끼게 한다. 우선순위는 신뢰도·전문성이다.
- **성공 기준**
  1. 실제 후기·대화 캡처·합격 사례·실적 수치·사업자 정보가 사이트에 노출된다.
  2. 후기나 사례를 추가할 때 데이터 파일만 고치고 빌드하면 페이지, 검색용 제목·설명, sitemap이 함께 갱신된다.
  3. 기존 메인·서브 페이지의 디자인과 동작은 바뀌지 않는다(회귀 없음).

## 2. 원칙·제약

- 실제로 증명 가능한 자료만 쓴다. 후기·수치를 만들어 넣지 않는다. 기존 후기 6개는 실제 후기를 정리한 것으로 확인됨(사용자 확인 2026-10-12).
- 수치 항목은 `근거`와 `기준 시점`이 필수다. 비어 있으면 빌드가 실패한다.
- 개인정보 보호: 수강생 이름은 `김○○` 표기를 유지하고, 캡처의 이름·연락처·프로필 사진은 가려진 상태로만 게시한다. 사용자가 가림 결과를 직접 확인하기 전에는 게시하지 않는다.
- 정적 사이트(GitHub Pages + Cloudflare)를 유지한다. 수정 방식은 "파일 수정 → 빌드 → 푸시"로 그대로 둔다.
- 기존 톤·색·폰트·카드 디자인을 이어 쓴다. 새 CSS 접두어는 기존 규칙에 맞춰 짧게 정한다.
- 구글 후기 별점 구조화 마크업(Review schema)은 쓰지 않는다. 사업자가 자기 후기에 쓰는 방식은 구글이 인정하지 않는다.
- 운영 사이트이므로 `site-trust` 브랜치에서 작업하고, 로컬 확인 후 사용자 승인을 받은 뒤에 master에 합친다.

## 3. 구조

### 3.1 데이터

```
data/
  reviews.json    후기 + 합격 사례 (한 파일)
  stats.json      실적 수치
  team.json       담당자 이력 (기존 소개 문구 이전)
  business.json   사업자·시설 정보
assets/proof/     가림 처리된 후기 캡처·합격 인증 이미지
tools/mask.py     이미지 가림(사각 영역 모자이크) 도구
build.py          build.sh 대체
```

**reviews.json 항목**
- 공통: `id`, `kind`(`text` | `capture` | `case`), `goal`(`degree` | `license` | `transfer` | `grad`), `period`(예: `2026.09`), `name`(`김○○`), `meta`(예: `직장인 / 학사 학위`), `featured`(메인 노출 여부), `source`(근거)
- `text`: `headline`, `body`
- `capture`: `image`(`assets/proof/...`), `alt`
- `case`: 위 + `slug`, `title`(예: `○○대 편입 합격`), `school`, `track`(전형), `profile`(연령대·전적 학력·보유 학점), `plan`(학점 계획 표), `duration`, `result`, `proofImages`, `planner`(team.json의 id), 검색용 `seoTitle`·`seoDescription`
- `case` 항목이 있으면 `/pages/reviews/<slug>/` 상세 페이지가 생성된다. `text`·`capture`는 상세 페이지가 없다.

**stats.json 항목**: `value`(숫자), `suffix`(선택, 예: `명+`), `label`, `asOf`(기준 시점), `source`(근거). `label`·`asOf`·`source` 중 하나라도 비면 빌드 실패.

**team.json 항목**: `id`, `name`, `role`, `photo`, `bio`(기존 소개 문구 그대로), `tags`, `career`(선택, 경력·자격 목록). 담당 분야는 기존 `role`과 `tags`로 표현한다.

**business.json 항목**: 상호, 대표자, 사업자등록번호, 신고번호, 연락처, 주소. 필요한 항목은 사용자의 사업 형태에 따라 확정한다.

### 3.2 빌드 (`build.py`)

- 입력: 기존 `sections/`, `pages/*/`의 HTML 조각 + `data/*.json`. 출력: 모든 `index.html`, sitemap.xml, 옛 주소 이동 페이지.
- 단계 1에서 기존 5개 페이지가 `build.sh`와 **바이트 단위로 동일**하게 만들어지는지 먼저 증명한 뒤에 기능을 추가한다.
- 후기·사례·수치·팀 영역은 템플릿 조각에 데이터를 채워 만든다.
- 검증 실패 시 빌드를 멈추고 이유를 알려준다: 필수 필드 누락, 존재하지 않는 이미지 경로, 중복 `slug`, 수치의 근거·기준 시점 누락, `case`의 `planner`가 team.json에 없음.
- sitemap.xml은 사례 상세 페이지를 포함해 자동 생성한다.

### 3.3 화면

**후기·합격 사례 페이지** (`/pages/reviews/`, 메뉴는 `수강생 후기` 그대로)
- 필터 한 줄: `전체 · 학위 취득 · 자격증 · 편입 · 대학원`. 탭과 후기 개수 표시는 없다.
- 한 그리드에 카드가 섞여 나온다: 글 후기(지금 카드), 대화 캡처 카드(클릭 시 확대), 합격 사례 카드(클릭 시 상세 이동).
- 합격 사례 상세: 익명 프로필, 목표, 학점 계획 표, 소요 기간, 결과·인증 이미지, 담당 플래너, 상담 신청 버튼.

**메인**
- 히어로 아래 실적 수치 띠(최대 6칸, 기준 시점·근거를 작은 글씨로 표기. 기존 카운트업 함수는 대상 섹션(`.es2`)이 사라져 쓰이지 않으므로 수치 띠 전용 카운트업 스크립트를 함께 출력).
- 후기 섹션은 `featured` 항목 6개를 데이터에서 가져온다. `후기 더보기`는 위 페이지로 연결.
- 하단 푸터 신설(사업자 정보, `business.json`).

**팀 소개**: 담당자 카드에 경력·자격·담당 분야 추가, 해당 담당자의 합격 사례로 연결. 기존 소개 문구는 유지.

**메뉴**: 변경 없음(4개).

## 4. 개인정보 가림 도구 (`tools/mask.py`)

- 입력: 원본 이미지 + 가릴 영역 목록(`x, y, w, h`). 출력: `assets/proof/`에 가림 처리된 이미지.
- 가릴 영역은 제가 이미지를 보고 지정하고, 사용자가 결과물을 확인한 뒤에만 사용한다. 원본은 저장소에 올리지 않는다(`.gitignore`로 `raw-proof/` 제외).
- 큰 이미지는 가로 1200px 이하로 줄여 저장한다.

## 5. 작업 순서와 검증

| 단계 | 내용 | 검증 |
|---|---|---|
| 1 | `build.py`로 교체 | 기존 5개 페이지 출력 바이트 비교 |
| 2 | 가림 도구, 자료 폴더 정리 | 가림 결과를 사용자가 직접 확인 |
| 3 | 기존 후기 6개를 `reviews.json`으로 이전, 후기 페이지 데이터화 | 이전 전후 화면 동일 |
| 4 | 새 후기·캡처·합격 사례 추가, 상세 페이지 생성 | 빌드 검증(필수 필드·이미지·slug) |
| 5 | 메인 수치 띠, 푸터, 메인 후기 섹션 데이터화 | 근거·기준 시점 필수 검사 |
| 6 | 팀 소개 보강 | 담당자↔사례 링크 확인 |
| 7 | 링크 자동 점검, 폭 3종(PC·태블릿·모바일) 확인, sitemap 갱신 후 승인받아 반영 | 가로 넘침 없음, 링크 200 |

반영 후: Cloudflare 캐시 비우기, 네이버·구글에 새 sitemap 제출.

## 6. 사용자에게 받아야 할 자료 (단계별로 요청)

1. 사업자 정보(상호, 대표자, 사업자등록번호, 신고번호, 연락처, 주소)
2. 후기·합격 인증 자료 폴더 경로
3. 메인 실적 수치 4개와 각 기준 시점·근거
4. 담당자별 경력·자격

## 7. 범위 밖 (이번에 하지 않는 것)

- 후기 별점 구조화 마크업, 후기 개수 표시, 탭형 후기 구분, 메뉴 추가
- 사이트 외부에서 후기를 자동으로 가져오는 기능
- 관리자 화면(데이터는 JSON 파일을 직접 고치거나 요청해서 수정)
