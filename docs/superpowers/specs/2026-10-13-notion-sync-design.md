# 노션 후기 자동 동기화 (설계)

작성일: 2026-10-13 / 대상: https://edu-solution.co.kr

## 1. 목표와 결정 사항

- **목표**: 팀원이 노션 데이터베이스에 후기를 적고 이미지를 올리면, 코드나 터미널 없이 사이트에 자동 반영된다.
- **결정(사용자 확인)**: 소스는 노션. 범위는 글 후기와 대화 캡처 이미지. 갱신 주기는 1시간(수동 즉시 실행 가능). 저장소는 공개 유지. 이미지의 개인정보 가림은 올리는 사람이 직접 한다.
- **범위 밖**: 합격 사례(`case`) 동기화, 이미지의 자동 가림, 노션 웹훅 즉시 반영, 노션 → 팀/수치/사업자 정보 동기화.

## 2. 흐름

1. 팀원이 노션 DB에 행을 만들고 **공개** 체크박스를 켠다. (공개가 꺼진 행은 절대 가져오지 않는다. 마지막 안전장치다.)
2. GitHub Actions가 매시간(`cron`) 또는 수동 실행(`workflow_dispatch`)으로 동기화 스크립트를 돈다.
3. 스크립트가 공개된 행을 읽어 `data/reviews.notion.json`(생성 파일)과 `assets/proof/notion-*.jpg`를 만든다.
4. `python build.py`(검증 포함)와 `python tools/check_links.py`가 통과하면 변경분만 커밋·푸시하고, 푸시가 GitHub Pages 배포를 일으킨다.
5. 검증이 하나라도 실패하면 아무것도 커밋하지 않고 워크플로가 실패한다(GitHub이 실패 메일을 보낸다). 사이트는 이전 상태를 유지한다.

## 3. 노션 데이터베이스 칸 (이름은 정확히 일치해야 함)

| 칸 이름 | 노션 형식 | 용도 | 필수 |
|---|---|---|---|
| 이름 | 제목(Title) | 수강생 표기. 예: `김○○ 님 (30대)` → `person` | 예 |
| 종류 | 선택 | `글 후기` 또는 `대화 캡처` → `kind` | 예 |
| 분류 | 다중 선택 | `학위 취득`, `자격증`, `편입`, `대학원` → `goal` | 예 |
| 공개 | 체크박스 | 켜진 행만 사이트에 반영 | 예 |
| 한줄제목 | 텍스트 | 글 후기의 제목 → `headline` | 글 후기 |
| 본문 | 텍스트 | 글 후기 본문 → `body` | 글 후기 |
| 소개 | 텍스트 | 예: `직장인 / 학사 학위 취득` → `meta` | 글 후기 |
| 배지 | 텍스트 | 예: `학사 학위` → `badge` | 글 후기 |
| 이미지 | 파일과 미디어 | 첫 번째 파일 → `image` | 대화 캡처 |
| 시기 | 텍스트 | 예: `2026.09` → `period` | 선택 |
| 대표 | 체크박스 | 메인 후기 섹션에 노출 → `featured` (글 후기만) | 선택 |
| 순서 | 숫자 | 작은 수가 앞. 없으면 등록 최신순 | 선택 |

## 4. 구성

```
tools/notion_sync.py            동기화 스크립트(표준 라이브러리만 사용: urllib, json)
site_build/notion.py            순수 변환 함수(행 -> reviews 항목, 서식 변환). 네트워크 없음, 단위 테스트 대상
data/reviews.notion.json        생성 파일(직접 수정 금지)
assets/proof/notion-*.jpg       내려받아 가공한 이미지(생성 파일)
.github/workflows/notion-sync.yml
tests/golden_data/data/*.json   기준본 테스트 전용 고정 데이터
```

- **합치기**: `load_site`가 `reviews.json`(수동)과 `reviews.notion.json`(생성)을 이어 붙여 하나의 목록으로 검증한다. 노션 항목의 `id`는 `notion-<행 ID 앞 8자>`이고, 두 파일에서 `id`가 겹치면 빌드 실패다. 기존 후기 6개는 `reviews.json`에 그대로 둔다.
- **노션 API**: `POST /v1/databases/{id}/query`를 `filter: 공개 = true`, 100개씩 페이지 넘김으로 호출. 헤더는 `Authorization: Bearer <토큰>`, `Notion-Version: 2022-06-28`. 429·5xx는 짧게 재시도하고, 계속 실패하면 실패 처리한다.
- **서식 변환**: 노션 텍스트는 외부 입력이므로 전부 HTML 이스케이프한 뒤 줄바꿈은 `<br>`로 바꾼다. 굵게는 본문에서 `<strong>`, 한줄제목에서 `<mark>`로 바꾼다. 그 밖의 서식(링크, 색 등)은 버린다. 노션 편집자가 HTML을 넣어도 사이트에는 영향이 없다.
- **이미지**: 노션 파일 주소는 약 1시간 뒤 만료되므로 동기화 때 바로 내려받는다. 파일 이름은 주소의 파일 UUID(쿼리 제외)로 만든 해시라 같은 이미지는 다시 받지 않는다. 가로 1200px 이하 JPEG로 줄이고 EXIF를 지운다(`tools.mask.mask_image(src, dst, [])` 재사용). 더 이상 참조되지 않는 `notion-*.jpg`는 삭제한다. 한 번 커밋된 이미지는 GitHub 기록에 남는다는 점은 변하지 않는다.
- **검증**: 기존 `validate_reviews`를 그대로 쓴다(필수 항목, 전화번호·이메일 차단, 이미지 경로 제한). 추가로 변환 단계에서 `종류`별 필수 칸이 비면 행 단위로 이유를 적어 실패한다.
- **기준본 테스트 분리**: 지금 `tests/golden`은 운영 데이터로 만들어져, 노션 동기화로 내용이 바뀌면 테스트가 실패한다. `load_site(root, data_root=None)`로 데이터 위치를 바꿀 수 있게 하고, 기준본 테스트와 스냅샷 스크립트는 `tests/golden_data/`의 고정 데이터로 빌드한다. 그러면 후기·수치·사업자 정보를 바꿔도 테스트가 흔들리지 않는다.

## 5. 워크플로

- 트리거: `schedule`(매시 17분), `workflow_dispatch`. `concurrency` 그룹으로 동시 실행 방지.
- 권한: `contents: write`만.
- 단계: checkout → Python 3.12 → `pip install -r requirements.txt` → `python tools/notion_sync.py` → `python build.py` → `python tools/check_links.py` → 변경이 있으면 `github-actions[bot]`으로 커밋(`Sync reviews from Notion`)하고 `git pull --rebase` 후 푸시.
- 비밀: `NOTION_TOKEN`(Secret), `NOTION_DATABASE_ID`(Variable).
- 전체 테스트(`pytest`)는 돌리지 않는다. 데이터가 바뀌는 작업이라 검증은 빌드와 링크 검사로 한다. 단위 테스트는 코드 변경 시 로컬에서 돈다.

## 6. 위험과 완화

| 위험 | 완화 |
|---|---|
| 가리지 않은 이미지가 올라가면 공개 기록에 영구히 남음 | **공개** 체크박스가 켜진 행만 반영. 올리는 사람이 가림 확인 후 켜기. README와 노션 DB 설명에 명시 |
| 노션 편집 권한 = 사이트 수정 권한 | 노션 공유 범위를 필요한 팀원으로 제한 |
| 노션 문구에 전화번호·이메일 | 기존 검증이 빌드를 막는다. 이미지 속 글자는 못 막는다 |
| 노션 HTML 삽입 | 전부 이스케이프. 변환 함수 테스트로 고정 |
| 토큰 유출 | GitHub Secret에만 저장. 저장소·로그에 출력하지 않는다. 노션 연동 권한은 해당 DB 하나로 제한 |
| `GITHUB_TOKEN` 푸시가 Pages 배포를 일으키지 않을 가능성 | 첫 실행 후 배포 여부를 확인한다. 안 되면 워크플로 마지막에 Pages 빌드를 요청하는 단계를 추가한다 |
| 제 GitHub 로그인에 `workflow` 권한이 없어 워크플로 파일을 푸시할 수 없음 | `gh auth refresh -s workflow`로 사용자가 한 번 승인한다 |
| 60일간 저장소 활동이 없으면 예약 실행이 꺼짐 | 동기화 커밋이 활동으로 잡힌다. 한동안 후기가 없으면 수동 실행으로 다시 켠다 |

## 7. 성공 기준

1. 노션에 글 후기 1개와 캡처 1개를 `공개`로 만들고 수동 실행하면 사이트 후기 페이지에 둘 다 나온다.
2. `공개`를 끄고 다시 실행하면 사라지고, 사용하지 않는 이미지 파일도 정리된다.
3. 필수 칸이 빈 행이나 전화번호가 든 행이 있으면 워크플로가 실패하고 사이트는 바뀌지 않는다.
4. 후기·수치를 바꿔도 `pytest`가 실패하지 않는다.
