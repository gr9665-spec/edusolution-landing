# 후기 글(블로그형) 재설계 (설계)

작성일: 2026-10-13 / 선행: `2026-10-13-notion-sync-design.md`(노션 동기화)를 이 문서가 대체·확장한다.

## 1. 목표와 결정 사항

- **목표**: 후기를 "카드(대표 이미지 + 제목 + 소제목 + 분류 + 날짜)와 상세 글" 구조로 바꾼다. 팀원은 노션에서 글을 쓰듯 후기를 올린다.
- **결정(사용자 확인 2026-10-13)**
  1. 후기 목록은 보내준 참고 사이트처럼 이미지가 위에 있는 카드가 가로로 놓인다. 카드를 누르면 상세 페이지가 열린다.
  2. 입력 항목은 **제목, 소제목, 내용, 분류, 대표 이미지**와 공개 여부뿐이다. 배지·소개·이름·시기·대표·순서·종류는 없앤다.
  3. 기존 후기 6개는 이미지가 없으므로 **로고가 들어간 기본 이미지**로 보여주고, 노션에서 이미지를 넣으면 바뀐다.
  4. 메인 페이지의 후기 섹션은 후기 카드가 **천천히 흘러가는 애니메이션**으로 보이고, "후기 더보기"로 목록 페이지로 이어진다.
- **범위 밖**: 댓글, 검색, 페이지 나누기, 작성자 표기, 합격 사례(case)·대화 캡처(capture) 종류(아래 5번에서 제거).

## 2. 데이터 모델

`reviews.json`(수동)·`reviews.notion.json`(노션, 생성 파일)의 항목은 모두 같은 `post` 종류다.

| 필드 | 설명 | 필수 |
|---|---|---|
| `id` | 수동 `r01`…, 노션 `notion-<행 ID 끝 12자>` | 예 |
| `kind` | 항상 `"post"` | 예 |
| `slug` | 주소 조각. 영문 소문자·숫자·하이픈. 노션은 `r-<행 ID 끝 12자>`, 수동은 `id`와 같게 | 예 |
| `title` | 제목(일반 텍스트) | 예 |
| `subtitle` | 소제목(일반 텍스트) | 예 |
| `category` | `degree`, `license`, `transfer`, `grad` 중 하나 | 예 |
| `image` | 대표 이미지 경로(`assets/` 안). 없으면 기본 이미지 `assets/review-default.jpg` | 아니오 |
| `date` | `YYYY-MM-DD`. 없으면 카드·상세에서 날짜를 숨긴다 | 아니오 |
| `body` | 본문 HTML(생성기가 만든 안전한 HTML만) | 예 |
| `source` | 근거 | 예 |

- `body`는 노션 블록에서 변환한 HTML이며, 허용 태그는 `p, h2, h3, strong, em, a, ul, ol, li, blockquote, hr, br, img, figure, figcaption`뿐이다. 빌드가 검증하지 않고 변환기가 이스케이프로 보장한다. 수동 항목은 같은 허용 목록을 만족해야 하며 검증이 태그를 검사한다.
- 기존 검증(필수 항목, 전화번호·이메일 차단, 이미지 경로는 `assets/` 안, id·slug 중복)을 모든 필드(본문 태그 안의 글자 포함)에 적용한다.

## 3. 노션

**데이터베이스 칸** (사용자 데이터베이스를 제가 노션 커넥터로 맞춘다)

| 칸 | 형식 | 용도 |
|---|---|---|
| 제목 | 제목 | `title` |
| 소제목 | 텍스트 | `subtitle` |
| 분류 | 선택(단일) | `학위 취득`, `자격증`, `편입`, `대학원` → `category` |
| 대표이미지 | 파일과 미디어 | 첫 파일 → `image`(없어도 됨) |
| 공개 | 체크박스 | 켠 행만 가져옴 |

- **내용은 칸이 아니라 페이지 본문**이다. 동기화가 `GET /v1/blocks/{page_id}/children`(100개씩 페이지 넘김, 하위 블록은 깊이 3까지 재귀)으로 가져온다.
- **날짜**는 노션의 등록 시각(`created_time`)을 `YYYY-MM-DD`로 쓴다. 목록은 날짜 내림차순(같으면 제목순).
- **지원 블록**: 문단, 제목 1·2(→`h2`), 제목 3(→`h3`), 글머리·번호 목록(연속된 항목을 `ul`/`ol`로 묶음), 인용, 구분선, 이미지. **서식**: 굵게, 기울임, 링크(`http`/`https`만). 그 밖의 블록·서식은 무시한다. 모든 글자는 이스케이프한다.
- **본문 이미지**와 대표 이미지는 지금과 같이 내려받아 JPEG(가로 1200px 이하, EXIF 제거)로 `assets/proof/notion-<해시>.jpg`에 저장하고, 쓰이지 않는 파일은 지운다. 캡션은 `alt`가 된다. 이미지의 개인정보 가림은 올리는 사람이 한다.
- 요청 한도(초당 약 3회)를 지키려고 블록 조회 사이에 짧게 쉬고, 429·5xx는 재시도한다.

## 4. 화면

**후기 목록** `/pages/reviews/`
- 카드: 위에 이미지(비율 16:10, 꽉 채움), 아래에 제목(2줄까지), 소제목(2줄까지), 줄 바닥에 분류 이름과 날짜. 호버 시 살짝 떠오른다.
- 열: 1100px 이상 4열, 600px 이상 2열, 그 아래 1열. 분류 필터(전체와 존재하는 분류)는 유지한다.
- 카드 전체가 링크다. 이미지의 `alt`는 제목이다.

**후기 상세** `/pages/reviews/<slug>/`
- 위에서부터 목록으로 돌아가는 링크, 분류 배지, 제목, 소제목, 날짜, 대표 이미지(기본 이미지는 숨김), 본문, 상담 신청 버튼과 "후기 더보기" 링크.
- `<title>`은 `제목 | 에듀솔루션`, 설명은 소제목, `og:image`는 대표 이미지(없으면 사이트 기본). sitemap에 자동 포함, 지운 후기의 상세 페이지는 다음 빌드에서 함께 지운다(기존 정리 로직 재사용).

**메인 후기 섹션**
- 최신 후기 최대 8개를 한 줄 카드(너비 약 280px)로 보여준다. 4개 이상이면 천천히(전체 약 60초) 왼쪽으로 흐르고 끊김 없이 반복한다. 반복용 복제 카드는 `aria-hidden`이고 탭 이동에서 제외한다.
- **멈춤·접근성**: 마우스를 올리거나 카드에 포커스가 가면 멈춘다. `prefers-reduced-motion: reduce`이거나 터치 화면(`pointer: coarse`)에서는 애니메이션 없이 가로 스크롤(스냅)로 보여준다. 4개 미만이면 흐르지 않고 나란히 둔다.
- 섹션 제목·소개 문구와 "후기 더보기"(→ `/pages/reviews/`), "나도 무료 상담받기" 버튼은 지금 그대로다.
- `대표`·`순서` 칸이 없어졌으므로 메인은 항상 **최신순**이다.

## 5. 제거와 이전

- **제거**: `capture`, `case` 종류, 사례 상세 페이지, 확대 보기(라이트박스), 팀 카드의 사례 링크, `text` 카드 렌더러와 관련 테스트. 사용된 적이 없고 새 구조와 겹친다. 필요해지면 다시 설계한다.
- **이전**: `data/reviews.json`의 기존 6개를 `post`로 바꾼다. `title` = 기존 한 줄 제목에서 태그를 지우고 `<br>`은 공백으로, `subtitle` = `이름 · 소개`(예: `김○○ 님 (30대) · 직장인 / 학사 학위 취득`), `category` = 기존 `goal`의 첫 값, `body` = `<p>` + 기존 본문, `date`와 `image`는 없음(기본 이미지). 일회성 이전 스크립트로 변환하고 삭제한다.
- **기본 이미지** `assets/review-default.jpg`: 네이비 배경에 로고를 가운데 둔 1200×750 이미지를 Pillow로 한 번 만들어 커밋한다.
- **기준본 테스트**: `tests/golden_data/data/*.json`을 새 구조로 바꾸고 기준본을 갱신한다.

## 6. 반영 순서와 위험

1. 코드·화면은 `review-posts` 브랜치에서 구현하고 로컬로 확인한다.
2. **노션 데이터베이스 칸 변경은 병합 직전에** 한다. 칸이 바뀌는 순간부터 옛 동기화 코드는 `종류` 칸이 없다고 실패하므로, 새 코드를 올린 뒤 바로 수동 실행한다. 그 사이에는 사이트가 바뀌지 않고 실패 메일만 갈 수 있다.
3. 현재 사이트에 올라간 시험 후기(노션 `공개` 켜짐)는 새 형식으로 다시 쓰거나 `공개`를 끈다.

| 위험 | 완화 |
|---|---|
| 흐르는 카드의 접근성·가독성 | 느린 속도, 호버·포커스 멈춤, 터치·동작 줄이기에서는 비활성화 |
| 노션 블록 변환 누락 | 지원 블록을 문서화하고, 미지원 블록은 무시하되 로그에 개수를 남긴다 |
| 본문 이미지 속 개인정보 | 올리는 사람이 가림. `공개`가 마지막 안전장치 |
| 요청 수 증가(후기 수 + 1회) | 블록 조회 사이 지연, 429 재시도 |
| 제거한 기능을 다시 쓰고 싶어짐 | git 기록에 남아 있어 복구 가능 |

## 7. 성공 기준

1. 노션에 제목·소제목·분류·대표 이미지·본문을 쓰고 `공개`를 켜면, 1시간 안에(또는 수동 실행으로 즉시) 목록 카드와 상세 페이지가 생긴다.
2. `공개`를 끄거나 행을 지우면 카드와 상세 페이지가 사라지고, 사용하지 않는 이미지도 정리된다.
3. 기존 후기 6개가 기본 이미지 카드로 나오고 상세 페이지가 열린다.
4. 메인 후기 섹션이 4개 이상이면 천천히 흐르고, 호버·포커스에서 멈추며, 터치·동작 줄이기에서는 가로 스크롤로 보인다.
5. 본문에 `<script>`를 넣어도 그대로 글자로만 보이고, 전화번호·이메일 형태가 있으면 동기화가 실패한다.
6. 후기·수치를 바꿔도 기준본 테스트는 흔들리지 않는다.
